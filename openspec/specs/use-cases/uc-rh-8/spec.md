# UC-RH-8: Проверить качество изменения

## Purpose

Зафиксировать основной вариант использования и его наблюдаемый результат.

## Requirements

### Requirement: UC-RH-8 — Проверить качество изменения

<a id="uc-rh-8"></a>
Система SHALL предоставлять воспроизводимый набор CI-проверок кода, документации, OpenSpec и релизного развёртывания.

**Основной актор:** разработчик.

**Цель:** доказать, что изменение проходит технические и продуктовые quality gates до публикации, а релизный тег развёртывается с доступными инфраструктурными зависимостями.

#### Scenario: Основной успешный сценарий

- **WHEN** разработчик отправляет merge request с изменением runtime или публичного контракта
- **THEN** CI проверяет тесты, frontend, Helm, quality gates, OpenSpec и синхронизацию Docsy metadata

#### Scenario: Успешное развёртывание релизного тега

- **WHEN** разработчик публикует релизный тег для commit из основной ветки
- **THEN** CI получает все образы приложения и инфраструктурных hooks, завершает Helm upgrade и оставляет релиз в состоянии `deployed`
