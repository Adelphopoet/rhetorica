# NFR-RH-002: Ограничения файлов

## Purpose

Зафиксировать измеримое ограничение качества соответствующей capability Rhetorica.

## Requirements

### Requirement: NFR-RH-002 — Детерминированная файловая policy

<a id="nfr-rh-002"></a>
Система MUST пропускать через сетевой периметр загрузки в пределах прикладного лимита и применять настроенные лимиты и проверку содержимого ко всем пользовательским загрузкам.

**Use Cases:** UC-RH-4

**Метрика:** доля загрузок в пределах прикладного лимита, которые достигают файлового API без отклонения на сетевом периметре, и доля загрузок, нарушающих лимит размера, количества, квоты, MIME/signature или OOXML safety, которые были отклонены приложением.

**Порог:** 100%; ingress принимает тело запроса размером до 50 MiB, а при стандартной конфигурации прикладной максимум составляет 25 МБ на файл, 5 файлов и 50 МБ на ход.

**Условия измерения:** аутентифицированная загрузка через опубликованный web ingress и файловый API с `ArtifactPolicyConfig` по умолчанию, включая валидные и вредоносные fixtures.

**Проверка:** Helm render/check конфигурации ingress, проверка аннотации live ingress, unit tests `ArtifactPolicy` и route tests файлового API.

#### Scenario: Файл в пределах прикладного лимита проходит ingress

- **WHEN** аутентифицированный клиент загружает через опубликованный web ingress валидный файл размером не более 25 МБ
- **THEN** запрос достигает файлового API и не отклоняется сетевым периметром из-за размера тела

#### Scenario: Файл превышает стандартный лимит

- **WHEN** клиент загружает файл размером больше 25 МБ при стандартной policy
- **THEN** система отклоняет загрузку с кодом `file_too_large` и не сохраняет содержимое
