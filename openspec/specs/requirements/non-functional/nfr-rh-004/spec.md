# NFR-RH-004: Задержка аналитического ответа

## Purpose

Зафиксировать измеримое ограничение качества соответствующей capability Rhetorica.

## Requirements

### Requirement: NFR-RH-004 — P95 latency quality gate

<a id="nfr-rh-004"></a>
Система MUST контролировать задержку аналитического runtime на закреплённом eval-наборе.

**Use Cases:** UC-RH-1, UC-RH-8

**Метрика:** `latency_p95` в миллисекундах.

**Порог:** не более 9000 мс.

**Условия измерения:** тот же CI eval-набор и runtime profile, которые заданы в `quality-gate-policy.v1.json`.

**Проверка:** `scripts/run_llm_quality_gates.py` сравнивает измерение с max policy и возвращает ненулевой exit code при превышении.

#### Scenario: P95 превышает gate

- **WHEN** измеренный `latency_p95` больше 9000 мс
- **THEN** quality-gate job завершается ошибкой и показывает нарушенную метрику

### Requirement: NFR-RH-004.1 — Сравнительный gate agent harness

<a id="nfr-rh-004-1"></a>
Система MUST проверять новый режим harness сравнением с baseline на фиксированных 30 задачах с тремя повторениями для каждого проверяемого LLM-подключения.

**Use Cases:** UC-RH-1, UC-RH-8

**Метрика:** доля cached input tokens, незакэшированные входные токены на задачу, latency_p95, корректность ответа и SQL, grounded_claim_ratio.

**Порог:** доля кэша не ниже 70% и baseline; незакэшированные входные токены ниже baseline; остальные метрики без ухудшения относительно baseline.

**Условия измерения:** одинаковые задачи, источники, параметры модели, повторения и режим прогрева; расходы compaction и retries включены в usage. Отсутствующие usage или оценки не считаются успешным измерением.

**Проверка:** сравнительный eval runner возвращает ненулевой exit code при нарушении gate или неполных измерениях.

#### Scenario: Новый режим проходит сравнение

- **WHEN** полный eval-набор выполнен и все сравнительные пороги соблюдены
- **THEN** отчёт допускает включение проверенного режима для данного подключения

#### Scenario: Кэш ниже порога

- **WHEN** измеренная доля кэша нового режима равна 65%
- **THEN** отчёт запрещает включение режима по умолчанию

### Requirement: NFR-RH-004.1.1 — Явный объём live-проверки

<a id="nfr-rh-004-1-1"></a>
Система MUST ограничивать количество новых задач live-evaluation явно заданным лимитом, равным одной задаче по умолчанию.

**Use Cases:** UC-RH-8

**Метрика:** число новых запланированных задач live-evaluation.

**Порог:** не более явно заданного положительного max-runs; по умолчанию не более одной задачи.

**Условия измерения:** число задач учитывает выбранные cases, подключения и повторения; отдельная задача может включать несколько model calls.

**Проверка:** CLI-тест с mock HTTP проверяет отказ до первого LLM-запроса при превышении лимита.

#### Scenario: Выборка превышает разрешённый объём

- **WHEN** выбранные cases и подключения требуют трёх новых задач, а max-runs не задан
- **THEN** collector завершается ошибкой до обращения к LLM и сообщает размер выборки


### Requirement: NFR-RH-004.1.2 — Точность офлайн-оценки стоимости

<a id="nfr-rh-004-1-2"></a>
Система MUST рассчитывать стоимость сохранённых model calls по явно заданному тарифу каждого подключения с использованием зарегистрированных счётчиков токенов.

**Use Cases:** UC-RH-8

**Метрика:** абсолютное отклонение оценки от суммы произведений числа токенов каждой непересекающейся категории на соответствующий тариф за 1000 токенов.

**Порог:** нулевое отклонение при полностью известных счётчиках и тарифах; отсутствие итоговой числовой оценки при неполных или некорректных данных.

**Условия измерения:** prompt_tokens включает cached_input_tokens; локальные FunctionTool/MCP входят в обычный input, отдельно тарифицируемые встроенные инструменты учитываются только по явному счётчику. Зарегистрированные вспомогательные вызовы и неуспешные диалоги сохраняются в оценке. Оценка по saved results не обращается к LLM и не заменяет сравнительную проверку качества.

**Проверка:** офлайн-тесты на фиксированных usage и тарифах проверяют Decimal-сумму, нулевой cache hit, неизвестный usage, некорректное разбиение input и отсутствие сетевых запросов.

#### Scenario: Расчёт по включающему кеш входу

- **WHEN** сохранён вызов с input=1000, cached=700 и output=100 при тарифах 0,3, 0,075 и 0,5 рубля за 1000 токенов соответственно
- **THEN** отчёт показывает оценку 0,1925 рубля без двойного начисления за 700 кешированных токенов

#### Scenario: Счётчик кеша отсутствует

- **WHEN** у одного сохранённого model call cache_usage_reported=false
- **THEN** отчёт помечает итоговую стоимость неизвестной, отдельно показывает известную часть и индекс неполного вызова и завершается с ненулевым exit code
