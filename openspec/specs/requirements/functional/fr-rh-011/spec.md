# FR-RH-011: Доступ к данным DWH Teradata

## Purpose

Зафиксировать наблюдаемое функциональное поведение соответствующей capability Rhetorica.

## Requirements

### Requirement: FR-RH-011 — Доступ к данным DWH Teradata

<a id="fr-rh-011"></a>
Система SHALL обрабатывать запросы пользователя на доступ к данным DWH Teradata: реагировать на вопросы доступа, проверять роли, определять доступ по витрине, сравнивать с сотрудником, создавать задачу в Jira для системы и выдавать инструкцию портал управления доступом.

**Use Cases:** UC-RH-9

#### Scenario: Запрос доступа к DWH

- **WHEN** пользователь запрашивает доступ к данным DWH Teradata
- **THEN** система определяет путь обработки и выполняет соответствующее подтребование (011.1–011.6)

#### Requirement: FR-RH-011.1 — Реагировать на вопросы доступа

Система SHALL реагировать на запросы пользователя о доступе к данным DWH Teradata и определять один из путей обработки: по роли, по витрине, по аналогии с сотрудником или для системы.

**Use Cases:** UC-RH-9

##### Scenario: Распознанный запрос доступа

- **WHEN** пользователь спрашивает о доступе к данным DWH
- **THEN** система определяет путь обработки (011.2, 011.3, 011.4 или 011.5)

#### Requirement: FR-RH-011.2 — Проверить доступ по роли

Система SHALL проверять наличие указанной роли у пользователя в Teradata (DBC.ROLEMEMBERSV) и сообщать результат.

**Use Cases:** UC-RH-9

##### Scenario: Роль есть

- **WHEN** пользователь указывает название роли, и роль есть у пользователя в DBC.ROLEMEMBERSV
- **THEN** система сообщает, что доступ уже есть

##### Scenario: Роли нет

- **WHEN** пользователь указывает название роли, и роли нет у пользователя
- **THEN** система выдаёт инструкцию по запросу в портал управления доступом (011.6)

#### Requirement: FR-RH-011.3 — Определить роль по витрине и проверить доступ

Система SHALL определять роль доступа по названию витрины через TERADATA.DB_Admin.V_GRANTS, проверять наличие этой роли у пользователя в DBC.ROLEMEMBERSV и сообщать результат.

**Use Cases:** UC-RH-9

##### Scenario: Доступ к витрине есть

- **WHEN** пользователь указывает название витрины, система определяет роль через TERADATA.DB_Admin.V_GRANTS, и роль есть у пользователя
- **THEN** система сообщает, что доступ уже есть

##### Scenario: Доступа к витрине нет

- **WHEN** пользователь указывает название витрины, система определяет роль через TERADATA.DB_Admin.V_GRANTS, и роли нет у пользователя
- **THEN** система выдаёт название роли и инструкцию по запросу в портал управления доступом (011.6)

#### Requirement: FR-RH-011.4 — Сравнить роли с сотрудником

Система SHALL сравнивать роли текущего пользователя и указанного сотрудника в Teradata (DBC.ROLEMEMBERSV) и возвращать перечень недостающих ролей либо подтверждение, что все роли есть.

**Use Cases:** UC-RH-9

##### Scenario: Есть недостающие роли

- **WHEN** пользователь указывает логин сотрудника, и у пользователя не хватает некоторых ролей
- **THEN** система возвращает перечень недостающих ролей с инструкцией по запросу в портал управления доступом (011.6)

##### Scenario: Все роли есть

- **WHEN** пользователь указывает логин сотрудника, и все роли совпадают
- **THEN** система сообщает, что все роли уже есть

#### Requirement: FR-RH-011.5 — Создать задачу для системы в Jira

Система SHALL создавать задачу в Jira (проект DATAGOV, тип «Задача») при запросе технического доступа для системы (СУЗ или Схема). В описание задачи система включает таблицу согласований, определяя согласующего для каждого запрошенного объекта:

- по названию витрины система определяет роли доступа (dg_bot.datamart_role_link);
- для каждой роли система определяет владельца (dg_bot.role_owner_link);
- владелец роли указывается в таблице согласований как согласующий (упоминание `[~login]`).

**Use Cases:** UC-RH-9

##### Scenario: Создание задачи для СУЗ

- **WHEN** пользователь запрашивает технический доступ для сервисной учётной записи (СУЗ)
- **THEN** система создаёт задачу в проекте DATAGOV с таблицей согласований в описании

##### Scenario: Создание задачи для Схемы

- **WHEN** пользователь запрашивает технический доступ для схемы
- **THEN** система создаёт задачу в проекте DATAGOV с таблицей согласований в описании

##### Scenario: У роли нет владельца

- **WHEN** система определяет, что у роли доступа нет владельца в dg_bot.role_owner_link
- **THEN** в таблице согласований указывается «Нет владельца роли»

#### Requirement: FR-RH-011.6 — Выдать инструкцию по запросу в портал управления доступом

Система SHALL выдавать инструкцию по запросу доступа в портал управления доступом, содержащую название роли и ссылку на портал портал управления доступом (https://access.example.com/), при отсутствии запрошенного доступа.

**Use Cases:** UC-RH-9

##### Scenario: Выдача инструкции

- **WHEN** система определяет, что у пользователя нет запрошенной роли
- **THEN** система выдаёт название роли и ссылку на портал управления доступом для запроса доступа
