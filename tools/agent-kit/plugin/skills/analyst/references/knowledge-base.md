# База знаний аналитика

Папка, совместимая с Obsidian. Создать при первом запуске, если её нет.

```
<ANALYTICS_KB>/
  README.md                       что это и как устроено
  knowledge/
    tables.md                     таблицы, которые уже понял
    sql-library.md                рабочие запросы
    business-context.md           термины, фильтры, поправки от людей
  reports/
    <slug>/<slug>.md              один отчёт = одна папка
    <slug>/<slug>.png             графики рядом с отчётом
    data/                         CSV и временные файлы
```

## Шаблоны файлов

`README.md`:

```markdown
# База знаний аналитика

Заполняется скиллом `analyst` плагина rhetorica-kit. `knowledge/` — что известно о данных, `reports/` — исследования.
Закрепить путь: `export ANALYTICS_KB=<этот путь>` в профиле оболочки.
```

`knowledge/tables.md`:

```markdown
# Таблицы

| Таблица | Коннектор | Что лежит | Grain | Ключ даты | Подвохи | Обновлено |
|---|---|---|---|---|---|---|
```

Одна строка на таблицу. Подвохи: дубли, статусы, которые надо фильтровать, часовой пояс, лаг обновления.

`knowledge/sql-library.md`:

```markdown
# Библиотека SQL

## <Что считает> (YYYY-MM-DD)

Источник: `<schema.table>`, коннектор `<name>`.

```sql
SELECT ...
```
```

`knowledge/business-context.md`:

```markdown
# Бизнес-контекст

- YYYY-MM-DD — <термин или правило>: <что это значит и откуда известно>.
```

## Правила пополнения

- Дописывать, не переписывать: новая строка или новый раздел. Исправление старого — с датой.
- Термин из `business-context.md` важнее твоей догадки. Конфликт — спросить.
- Ничего секретного: без токенов, паролей, персональных данных в примерах.
