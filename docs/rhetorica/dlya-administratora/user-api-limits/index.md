# Лимиты API пользователей

По умолчанию локальные учётные записи не имеют индивидуального часового лимита. Администратор может ограничить только выбранного пользователя, не меняя поведение остальных.

## Настройка

1. Откройте административную консоль и раздел **Access**.
2. В строке нужного локального пользователя нажмите **Limit**.
3. Включите **Limit API requests for this account**.
4. Укажите количество запросов за скользящий час и сохраните настройку.

Лимит учитывает все аутентифицированные запросы пользователя к `/v1`, включая запросы через браузерную session, Personal Access Token и OAuth credential. Эти способы доступа используют одну общую квоту. `OPTIONS`, публичные endpoints, `/mcp`, а также сброс и отключение собственного лимита администратором в эту квоту не входят.

После исчерпания квоты API возвращает `429 Too Many Requests`, `Retry-After` и поля `RateLimit-*`. Когда самый ранний запрос выходит за пределы последних 60 минут, освободившаяся квота доступна автоматически.

## Изменение и отключение

Изменение числа запросов сохраняет уже накопленное использование текущего окна. Кнопка **Reset usage** очищает использование, но оставляет величину лимита. Выключение переключателя удаляет индивидуальную политику и возвращает прежнее неограниченное поведение.

Если Redis недоступен, пользователь с включённым жёстким лимитом получает `503 rate_limit_unavailable`. При этом администратор всё ещё может отключить собственный лимит. Пользователи без индивидуального лимита продолжают работу без обращения к счётчику.
