# Для администратора

Администратор управляет доступными возможностями, но не подменяет governance DWH. Коннектор должен иметь минимально необходимые права, понятное описание назначения и ограниченный scope.

- [Коннекторы](connectors/) — подключение систем и проверка секретов.
- [Агенты и skills](agents-skills/) — управление инструментами и политиками выбора.
- [Лимиты API пользователей](user-api-limits/) — индивидуальная квота локальной учётной записи.

## Диагностика LLM-вызовов

Для расследования таймаута найдите в логах API события `llm.call.started`,
`llm.call.first_chunk` и `llm.call.completed` по `conversation_id`. Поля `run_id`,
`call_id`, `call_index` и `phase` связывают вызовы одного хода, включая compaction.
Итоговая запись содержит исход, длительность, время первой и последней наблюдённой
активности, объёмы текста, reasoning и аргументов инструментов в символах, а также
тип терминального события. Содержимое чанков в эту диагностику не копируется.

История через `GET /v1/chat/conversation/{conversation_id}` возвращает snapshot
вызовов каждого ответа в `messages[].capability_trace.runtime_context.llm_calls`.
Диагностика находится в поле `diagnostics` каждой записи. `usage_reported=false`
означает, что провайдер не сообщил расход токенов; нули такой записи не являются
измеренным расходом.

Время чанков отражает получение публичных событий SDK, а не сетевую активность.
Для непотоковых вызовов эти отметки отсутствуют. При аварийном завершении процесса
может сохраниться только стартовый лог. Лимит `model_timeout` применяется нативным
SDK к одному вызову модели; появление текста или reasoning не перезапускает его.
