Личный сценарий редактирует его владелец. Общий сценарий публикует администратор. Результаты общего сценария принадлежат пользователю, который его запустил.

## Редактор

В каталоге создайте сценарий или откройте редактор существующего. Слева находится список типов шагов, в центре — граф, справа — настройки выбранного шага, снизу — тестирование. Перетащите связь от правого порта одного шага к левому порту следующего. Связь задаёт порядок выполнения; конкретные данные указываются в разделе **Входы шага**.

Каждый вход получает константу, параметр запуска или выход предшествующего шага. Типы: текст (`string`), число, boolean, JSON, таблица, файл и список файлов. Названия выходов видны на узле. Параметры и выходные JSON-схемы проверяются сервером.

**Сохранить** обновляет черновик. **Опубликовать** создаёт новую неизменяемую версию. Конфликт ревизии означает, что другой редактор уже сохранил изменения: можно загрузить его черновик, сохранив возможность отменить замену через undo. ⌘/Ctrl+Z отменяет изменения, Shift+⌘/Ctrl+Z повторяет, ⌘/Ctrl+D копирует выбранный шаг, ⌘/Ctrl+S сохраняет. Delete удаляет выбранный элемент графа.

## Быстрый старт

При создании выберите «Анализ данных», «SQL и выгрузка» или «Ответ агента», затем коннектор и агента. Редактор откроет соединённую цепочку с настроенной передачей данных. Измените SQL и инструкции под свою задачу.

Выберите шаг и добавьте следующий через левую панель — он вставится в последовательность. Для условий и параллельных ветвей соедините порты вручную. Настройки входов показывают параметры и результаты предшествующих шагов: выберите нужный выход, тип определится автоматически. Имя входа можно изменить, текст вводится в текстовом поле, число — в числовом, boolean — переключателем «Да / нет». Вложенный JSON и необязательные входы находятся в дополнительных настройках.

Готовую цепочку также можно выбрать в левой панели существующего редактора. Она заменит граф; отмена доступна через undo. Тестовая панель раскрывается снизу, оставляя большую часть экрана холсту.

## SQL → файл → Python

1. В SQL-шаге выберите существующий коннектор. В SQL используйте параметры-значения вида `:month`; создайте одноимённый вход шага. SQL Guard и ограничения коннектора действуют при каждом выполнении.
2. Соедините SQL с Python. Во входах Python откройте **Выбрать параметр или результат** и выберите **SQL-запрос → file · Файл**. Вход `file` появится автоматически. В шаблоне «Анализ данных» эта связь уже настроена.
3. Python получает путь к полному сохранённому XLSX. Пример:

```python
import pandas as pd

df = pd.read_excel(inputs["file"])
summary = df.groupby("category", as_index=False)["amount"].sum()
summary.to_csv("/workspace/output/summary.csv", index=False)
result = {"rows": len(df), "categories": len(summary)}
```

Выход `result` содержит JSON, `files` — ссылки на опубликованные файлы. Следующий Python-шаг может получить `files` и прочитать `inputs["files"][0]`. Если передан выход SQL `table`, путь к файлу находится в `inputs["table"]["file"]`.

Превью не является источником данных для следующего шага. В XLSX попадают все строки сохранённого результата в пределах лимита SQL. Если запрос достиг ограничения, результат показывает признак возможного усечения. Исходные и производные артефакты сохраняются в object storage; ожидание подтверждения или закрытие браузера не удаляет их.

Один Python-шаг принимает до пяти файлов плюс внутренний манифест значений. Действуют текущие ограничения размера входов, выходов, времени, памяти и сети sandbox. Код не получает секреты коннекторов или доступ к файловой системе worker.

## Ветви и подтверждения

У условия есть порты `true` и `false`. Неактивные ветви получают статус «Пропущен». Объединение ждёт все активные ветви. Вход из условной ветви должен быть необязательным с явно заданным значением по умолчанию, если его результат может отсутствовать. Циклы и недостижимые узлы не публикуются.

Узел подтверждения показывает инициатору сообщение и данные. **Продолжить** разблокирует следующие шаги; **Отклонить запуск** завершает выполнение. Закрытие вкладки ничего не отменяет. Для остановки используйте **Отменить** на странице запуска.

## Агенты, тесты и AI-помощь

Для LLM-шагов выберите агента, инструкции и инструменты. Инструмент должен быть разрешён и сценарием, и шагом; действуют также права пользователя и политика агента. Каждый шаг получает свой контекст. Структурированный JSON доступен только при поддержке коннектором и проверяется по выходной схеме.

В нижней панели заполните формы тестовых входов. Редактирование всего JSON доступно в дополнительной настройке. Можно проверить весь черновик или выбранный шаг на явно заданных входах. Загрузка файла для теста связывает его с вашим разговором. Сохранённый тест включает входы и ожидаемую JSON Schema результата. В истории выполнения доступны входы, выходы, фактический SQL, код, ошибки, инструменты, длительность и известный расход токенов.

AI-помощник предлагает граф по описанию и изменения SQL/Python. Во время ожидания показываются спиннер и прошедшее время. При неполном ответе модели можно повторить запрос, сократить изменение или выбрать агента с большим лимитом ответа; черновик остаётся прежним. Перед применением показывается сравнение. Если граф изменился во время генерации, запросите новое предложение. Некорректное предложение применить нельзя. Применение меняет только черновик; тестирование и публикация остаются отдельными действиями.

Старые prompt-сценарии доступны как legacy-версии с одним LLM-шагом. После публикации графа новые запуски используют workflow-версию. Файлы доступны во фронтенде и обслуживающем его API; Mattermost сохраняет прежнее ограничение.
